AWS Kiro チームが「週1,000件の PR を人が全行読まずに安定させる」運用を公開——指摘の重大度ティア分けと「PR Readiness」判定

DEVPMCONSULT

AWS Japan ブログ（10月28日、原文は10月26日）で Kiro Crew チームが、週1,000件の PR をマージしながら品質を保つ方法を紹介した。最初の人間による全件レビューは1日も続かず、自動テストと検証で担保する方針に切り替えたという。指摘は重大度で分け、ブロッキングは同じ PR で直し、軽微なものは後続の課題にする。ブロッキングには場所・根拠・発生条件・結果が必須で、説明できない指摘は参考意見に落とす。レビュアーは設計・第一原理・UX の役割と、異なるモデルファミリーで分担し、指摘は1ラウンドで出し切る。「失敗がない」ではなく「期待されるチェックがすべて実行されて成功した」を1つの合否信号にまとめ、prepare-pr スキルが緑になるまで修正と push を繰り返す。全 PR で80件以上のチェックを走らせ、テストカバレッジは90%超、開発時間の約20%を自動化基盤に充てているという。

どう試す：自チームの AI レビュー設定に「ブロッキング指摘は場所・根拠・発生条件・結果を書けなければ参考意見にする」というルールを入れ、1週間分の PR で往復回数が減るかを測る。
  • DEVレビュー規約を「指摘の書式」まで落とすと、AI レビュアーのノイズ（根拠のない指摘）を機械的に切り分けられる。合否信号を1つにまとめる発想もそのまま真似できる。
  • PM見積もりに「自動化基盤の構築＝開発時間の約2割」を入れる根拠になる。人間レビューを前提にしたスループット計画は、PR が増えた時点で破綻する。
  • CONSULT「AI が書いたコードの品質は誰が保証するのか」という質問に、人の目視ではなく検証の仕組みで答える具体例として示せる。数値は AWS 自身の報告で、他社の再現は未確認。
出典： AWS Japan ブログ「週 1,000 件の PR でもソフトウェアファクトリーを安定させる方法」（2026-10-28）
コメント：「人間が全行を読まない」ことを前提に、責任の置き場を「レビュー記録」に移している点が、他の組織が最も議論を呼びそうな部分だ。

CONSULTDEVPM

Preferred Networks は10月27日、国産基盤モデル PLaMo 3.1 Prime を PLaMo Chat、PLaMo API、オンプレミスで同日から提供開始した。Web 検索に加え、調査計画の立案から出典付きレポート作成までを自律的に行う Deep Research を、オンプレ環境でも使えるようにした。社内文書の検索システムと連携すれば、社内文書だけ、または Web と組み合わせた調査もでき、閉域環境での利用も可能とされる。ハルシネーション関連の8ベンチマークで前モデル比平均約15%の改善、投機的デコーディングで処理速度は1.7倍、非推論モードでは出力トークンを約90%削減したと説明している。一方、STEM・コーディング・Web 検索を伴う回答では競合を下回ったと PFN 自身が報告している。API は Free プラン（上限あり・無料）と Standard プラン（100万トークンあたり入力60円・出力250円）があり、PLaMo Chat の Deep Research は11月30日まで1日2回まで無料。

Anthropic が Claude Enterprise 向けに「Smart reports」「アプリ内アンケート」「グループ共有予算」を提供——AI 費用が何を生んだかを可視化

PMCONSULT

Anthropic は10月28日、Claude Enterprise 向けの3機能を一般提供とした。Smart reports は、選んだ期間・製品のチームの会話記録を抽出して分析し、作業を流れごとにまとめ、費用・成果物・つまずきやすい点を示す。スキル化すべきワークフローなどの提案も付く。目的は導入状況の把握と計画で、個人の評価や雇用判断には使わないとされる。アプリ内アンケートは、返信後に表示される短いカードで、既定の質問は価値と節約時間。管理者が質問・対象・タイミングを変えられ、回答は表計算へ書き出せる。グループ共有予算は、グループごとに月次の共有枠を設け、個人の上限も併存する（先に尽きた方で止まる）。管理者は50・75・95・100%でメール通知を受け、メンバーはアプリ内から追加を申請できる。HIPAA 構成や顧客管理の暗号鍵など、構成によって利用可否が異なる。

  • PMAtlassian 調査など「時間が浮いたという自己申告」が当てにならない局面で、アンケート（自己申告）と会話記録の分析（実態）を突き合わせる材料になる。共有予算の4段階通知は、費用統制の運用にそのまま使える。
  • CONSULT「AI を配ったが効果が見えない」という相談に、必要なデータ（費用・成果物・阻害要因・自己申告）の組み合わせを示せる。ただし会話記録を分析する機能なので、従業員への説明と社内規程の整理が前提になる。
出典： Claude「Smart reports, in-app surveys, and pooled group budgets」（2026-10-28） TechCrunch（2026-10-28、報道）
Enterprise プランのみ。Smart reports と共有予算の学習利用の扱いは該当ページに記載がなく、商用規約またはヘルプセンターでの確認が必要。
コメント：「分析対象は会話記録」という点を従業員にどう説明するかが、機能そのものより先に決めるべき論点になる。

GitHub Universe 2026：Copilot app・Fusion・自動化・「Code review Max」を発表——Enterprise は別契約なしで利用、課金は AI クレジット従量

DEVPMCONSULT

GitHub は10月28日、Universe で「エージェント優先」の機能群を発表した。Copilot app は、課題からマージまでの作業をエージェントとツールで束ねる。Copilot Fusion はタスクごとに1つ以上のモデルでの実行方法を選び、Fusion Max は Artificial Analysis Coding Agent Index で Opus 5.5 Max に2点差まで迫りつつ、費用は半分、1タスクあたりの時間は40%短いと GitHub は述べている。Copilot projects は複数リポジトリのエージェント作業を並列に管理し、クラウドエージェントのセッションは GitHub アプリ・VS Code・CLI・Web をまたいで継続できる。Copilot automations は手動・イベント・スケジュールで動くクラウド上の自動ワークフローで、改善案は人が承認する。Code review Max は ReviewBench の高重大度指摘で最高の F1 を出したとする深い審査ティアで、Lite・Balanced も残る。GitHub Enterprise 顧客は別サブスクリプションなしで全機能を使え、使った AI クレジット分を支払う。提供は GitHub の営業経由で、セルフサービスは「近く」。

  • DEVEnterprise 契約があれば営業経由で試せる。複数リポジトリにまたがる変更と、スケジュール実行の自動化を、小さなリポジトリ1つで試して挙動を確認する。
  • PM席数課金から AI クレジットの従量課金に寄る。ツール費用は使われた量で変動するため、月次の消費上限と通知を先に決めておく。

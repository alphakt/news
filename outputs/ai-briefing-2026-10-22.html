PHP プロジェクトは10月21日（UTC 14:00）、PHP 8.x 系の2件の脆弱性（CVE-2026-109618、CVE-2026-109619、いずれも CVSS v4.0 で 9.2）を修正するセキュリティリリースを出した。前者はメモリ不足時の処理が中途半端な内部データを残す問題、後者はリクエスト固有の内部状態が解放後も残り、同じワーカーの次のリクエストで使われる問題で、どちらも認証なしで任意コードを実行され得る。リスクが最も高いのは mod_php とされる。一時的な緩和策（memory_limit=-1、post_max_size を小さくする、session.upload_progress.enabled=0）はあるが、PHP 側は「完全な対策は更新のみ」としている。Simon Willison の記事によれば、Wiz Research が8月24日に PHP チームへ報告し、最初の1件は AI ツールで見つけたという。CVE ID が10月20日に漏れたため、公開は予定の22日から前倒しされた。OpenAI は PHP のバージョンを HTTP ヘッダーなどから判定する OSS「php2shell-checker」を公開している。

どう対応する：PHP を使う自社・顧客の Web サーバーで、バージョンを 8.5.12 / 8.4.27 / 8.3.36 / 8.2.35 以上に更新する（OS のパッケージ版は配布元の修正有無を確認）。8.1 以前は公式の更新が終わっており、PHP チームが公表した最小限のバックポートか移行が要る。
  • DEV自分たちの PHP 環境（本番・検証・古い社内ツール）を棚卸しして更新する。バージョン判定ツールはヘッダーが隠れていると「不明」になり、「不明」は安全の意味ではない。
  • CONSULTPHP 製の基幹・社内システムを持つクライアントから「うちは大丈夫か」と聞かれる。バージョン確認と更新計画を今週の提案に入れられる。PHP 8.2 は2026年12月31日にサポートが終わる点も併せて伝えられる。
  • PM運用保守を請け負う案件では、緊急パッチの工数と停止時間を早急に見積もり、顧客に連絡する担当と期限を決める。

PyPI の LiteLLM 1.107.0 に認証情報を盗むマルウェアが混入——SSH 鍵・クラウド認証・LLM の API キーを外部に送信、PyPI は当該版を削除

DEVPMCONSULT

セキュリティ企業 SafeDep が10月21日に公表した。LiteLLM 1.107.0（全 wheel とソース配布）をインストールすると、site-packages に cook.pth、cook.py、sitecustomize.py が置かれる。cook.pth は Python のプロセスが起動するたびに動き、SSH 鍵、クラウドや CI/CD の認証情報、AI ツールのトークン、ブラウザのパスワード、LiteLLM プロキシのデータベースにある LLM プロバイダーのキーを集めて暗号化し、外部ドメインへ送る。sitecustomize.py は毎時動くバックグラウンドプロセスを起動し、GitHub 上のファイルから接続先を読み、そこからコードを取得して実行する。SafeDep によると、1.106.2、1.107.0rc1、1.107.0rc2 と、companion の litellm-proxy-extras 0.4.110、litellm-enterprise 0.1.78 は影響を受けない。PyPI は 13:40 UTC 時点で 1.107.0 を削除済みと記載されている。

どう対応する：pip list / lockfile で litellm==1.107.0 が入っていないか確認する。入っていた環境は、SafeDep の記事に載っている痕跡（cook.pth などのファイル、/tmp 配下のロックファイルなど）を調べ、その環境の鍵・トークンはすべて失効させて再発行する。当面は 1.106.2 に固定する。
  • DEVLLM ゲートウェイとして LiteLLM を使う環境（開発機、CI、社内プロキシ）の依存を確認し、バージョンを固定する。インストールした端末の認証情報は漏えい前提で扱う。
  • PM依存パッケージの自動更新を開いたままにしているプロジェクトは、更新の反映までに待機期間を設ける運用を検討する。LLM の API キーも他の秘密情報と同じ失効手順に含める。
  • CONSULTクライアントが AI 基盤の部品として OSS ゲートウェイを採用しているかを確認する材料になる。ソフトウェア部品表（SBOM）と依存の固定を提案に含められる。

デジタル庁が、Excel・CSV を機械可読なデータに直すためのチェックツール「Harunobu」を公開——100点満点の採点と違反箇所の一覧、AI 判定補助は任意

デジタル庁は10月21日（新着一覧の日付）、行政データの「機械可読性に関するルール」への適合を調べるツール Harunobu を掲載した。Excel、CSV、TSV を読み込み、100点満点の点数と、違反の場所・理由を一覧で示す。重大な違反があるとその水準の点は0になる。使い方はブラウザ画面（Streamlit）、コマンドライン（harunobu analyze）、Python API の3通りで、GitHub で公開されている。判定は既定ではローカルの機械的なロジックで行われ、ファイルの内容は外部に送られない。任意の「AI による判定補助」を有効にすると、利用者が設定した外部の AI API（Gemini、ChatGPT、Claude など）にデータが送られるため、組織のセキュリティ方針を確認するよう注意書きがある。判定できないルールもあり、制約は GitHub に記載されている。

  • CONSULT「神 Excel」を抱える自治体・企業に、AI 活用の前にデータ整備が要ることを示す材料になる。AI 判定を使う場合は、データの外部送信の可否を先に確認する必要がある。
  • DEV社内の表データを RAG や分析に使う前の品質チェックに、CLI で組み込める可能性がある。適用範囲は行政データ向けのルールである点に注意。

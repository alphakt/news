GMO サイバーセキュリティ byイエラエが、国内の相次ぐ不正アクセスの攻撃元で AI 自律型ペネトレーションテストシステム「ARTEX」の使用を確認——日本企業約20社を業種を絞って狙い、8社が漏えいを公表済み

GMO サイバーセキュリティ byイエラエは10月19日、10月14日の前回記事の続報として、日本企業を狙った侵害事案の攻撃元インフラを調べた結果、AI による自律型ペネトレーションテストシステム ARTEX が使われていたことを確認したと公表した。前回はフォレンジックログから AI による攻撃の可能性が高いと推定していたもので、今回それが裏付けられた。観測できた範囲では攻撃元インフラはほぼ日本のみを標的とし、約20社を狙い、うち9社は同業種だった。国と業種を絞ったキャンペーンごとに別の攻撃用ホストを用意しているとみられ、デジタルギフト、保険・金融、EC・物流など業種の異なる攻撃インフラがさらに6台見つかっている。標的とされた日本企業のうち8社は、9〜10月にすでに情報漏えいを公表している。CrowdStrike が9月下旬から韓国の金融機関への攻撃で ARTEX が使われたと報じており、同じ手口が日本にも向けられたと同社は推察する。日本と韓国以外が狙われているかは調査中で、情報は法執行機関に共有された。記事に具体的な対策の記載はない。

どう対応する：GMO の続報で標的業種に挙がったクライアント（EC・物流・保険・金融・ギフト・教育など）には、外部公開資産の脆弱性診断と修正状況の棚卸しを今週中に提案する。AI が脆弱性を自動で探して突く前提で、診断の頻度と修正の期限を短くする（具体的な対策は出典に記載がないため、これは編集部の提案である）。
  • CONSULTクライアントから「AI を使った攻撃は本当に来ているのか」と聞かれたとき、国内企業の漏えい公表8社と結び付いた一次の分析を示せる。標的業種に当たる顧客には、診断と修正の優先度を上げる提案の根拠になる。
  • PM進行中の案件で外部公開する環境がある場合、脆弱性の修正期限と診断の実施時期を前倒しするかをリリース計画で確認する。
  • DEV攻撃側が脆弱性の探索から侵入までを自動化している前提で、公開 API や管理画面の既知の脆弱性・設定不備を放置しない運用にしておく必要がある。

デジタル庁が約18万人の政府職員向けに AI エージェント環境の提供を開始し、AISI の協力で作った安全基準「源内基準」を公開——2027年2月頃には環境ごと OSS 化の予定

CONSULTPMDEV

デジタル庁は10月20日、ガバメント AI「源内」で、約18万人の職員に2種類の AI エージェント利用環境を提供すると発表した。手軽にエージェントを作って動かせる「エージェントチャット」は各府省庁へ順次導入し、高度なエージェントを作れる「源内工房」は令和8年12月頃までの導入を目指す。両環境は「源内 OSS Ver.2.0」として令和9年2月頃を目途に公開される予定で、地方公共団体や民間事業者も利用・改変・再配布できる形にする方針という。あわせて公開された「源内基準」は、職員が AI エージェントを安全に使うための基本的な考え方と遵守事項をまとめたもので、AI セーフティ・インスティテュート（AISI）の協力を得て作られた。「利用者」「管理者」「開発者」の3者それぞれの責務を定め、民間事業者が安全性と活用を両立させる際のモデルになるとされる。個別の要件は添付 PDF にあり、今回はその本文までは確認していない。

どう試す：源内基準の PDF を取得し、クライアントのエージェント利用規程やレビュー観点（利用者・管理者・開発者の責務分担）と並べて差分を確認する。
  • CONSULT官公庁・自治体や、それらに納める企業から「政府はどんな基準でエージェントを使わせるのか」と聞かれる。提案書のガバナンス章で、利用者・管理者・開発者の3者に責務を分ける枠組みを参照できる。
  • PMエージェントの権限と責務を役割別に分ける考え方は、社内の利用ルールや案件のレビュー体制の設計にそのまま使える。OSS 版の公開時期（2027年2月頃）は調達・内製判断の時間軸になる。
  • DEV2027年2月頃に環境が OSS で公開される予定のため、構成を見て自社のエージェント基盤と比較する材料になる。

重要度：中

Microsoft が「エージェントは新しい内部者」として Guardian Agents と動的権限を発表——Defender の検出対象は Claude Code・Codex など60種のローカルエージェントに拡大

PMCONSULTDEV

Microsoft は10月19日のセキュリティブログで、AI エージェントを内部者になぞらえ、Project Perception の中に Playbooks と Guardian Agents を加えると発表した。方針や承認の境界は人が決め、Guardian Agents がリスクの変化の説明、証拠の調査、封じ込めの提案・実行を機械の速度で行う。Microsoft Defender の検出は60種のローカルエージェント（Claude Code、OpenAI Codex、GitHub Copilot を含む。従来から35種増）に広がり、見つけたエージェントは所有者・活動・リスクを追う統合レジストリに載せられる。制御として、エージェントを権限ゼロから始め、タスクごと・期限付きで権限を与える Dynamic Permissions、複数のシグナルでリスクを採点する Dynamic Agent Risk、リスクに応じて読み取りのみ許可や隔離まで段階的に絞る Dynamic Conditional Access を挙げ、影響の大きい操作には人の承認を求められるとする。ただしプレビューか一般提供か、提供時期はブログに書かれていない。Ignite 2026（11月17〜20日）が案内されている。

  • PM社員が持ち込む Claude Code や Codex の把握と、タスク単位・期限付きの権限という考え方を、案件のエージェント運用ルール（誰が何を許可するか）に落とせる。提供時期が不明なため、製品導入を前提にした計画は立てられない。
  • CONSULTMicrosoft 環境のクライアントから「社員が勝手に使うエージェントをどう管理するか」と聞かれる場面で、主要ベンダーの設計方針として示せる。提供状況は Ignite で確認する必要がある。
  • DEV開発者が使うエージェントがレジストリと権限制御の対象になりうる。権限の設計は「既定で権限なし、タスクごとに付与」が前提になる。

重要度：低

NEC が Claude Code を Amazon Bedrock 経由で全社展開——CoE・チャンピオン制度と工程別 Skills で「約3万人の AI ネイティブエンジニア体制」を目指す

CONSULTPM

AWS Japan のブログ（10月20日）が、NEC と Anthropic Japan の協力のもと、NEC の Claude Code 展開の進め方を紹介している。SI サービス CoE が中心になり、各事業部門に部門 CoE を置き、現場をリードするチャンピオンを育てる体制である。業務手順やノウハウをまとめた Skills で知見を標準化し、要件定義・設計・製造・テストの各工程向けの専門 Skills を整備中という。NEC と AWS が共催したワークショップは、7月16日の入門編と8月25日の応用編（部門推薦の中級者限定、ハーネスエンジニアリングの実践）の2回で、延べ158名が参加した。入門編のアンケートでは、開発業務で活用したい人が93%、満足度が88%だった。全社員向けには Amazon Bedrock 上の Claude Desktop を展開し、約3万人の体制は目標として書かれている。一方、工数削減などの定量的な業務効果と、利用ルールや統制の具体策は記事に載っていない。

  • CONSULT日本の大手 SIer が「CoE＋チャンピオン＋工程別 Skills」で展開している実例として、競合の動きと、クライアントの全社展開提案の型の両方に使える。効果の数値がまだ無い点も含めて伝える必要がある。
  • PM教育を入門編と部門推薦の応用編に分け、個人利用からチーム・部門単位の活用へ移す段階設計は、展開計画の工程にそのまま使える。
出典： AWS Japan Blog「約3万人のAIネイティブエンジニア体制へ ― NEC は Claude Code をどう全社展開しているのか？」（2026-10-20）
満足度などは入門編ワークショップ参加者のアンケートで、業務効果の実測ではない。3万人は目標値である。

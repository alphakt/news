Kiro が自社エージェント基盤の26関数を Lean で形式検証——96個の性質のうち18個が反例で崩れ、「常に許可」パスの glob 誤判定などの不具合が見つかった

DEVPMCONSULT

AWS の Kiro チームは、エージェント基盤（ハーネス）のうち26の関数（Kiro CLI v3 と Kiro Crew を含む）を証明支援系言語 Lean 4 でモデル化し、96個の性質を調べた。結果は、70個が前提のもとで全入力について証明され、2個が有界検証、18個が反例で否定（各反例は実コードで再現）、6個が部分結果や観察である。証明できた例には、サブエージェントの権限判断が親を超えないこと、重複添付の除去でプロンプトキャッシュの接頭辞が変わらないことがある。見つかった不具合は、キャンセル直後に再実行されるジョブ、UTF-16 単位の切り詰めで CJK のページが意図の約1.5倍に達する出力、「常に許可」パスの glob 文字（Next.js の [slug] など）が想定より広く許可される例などで、セキュリティ問題はないとされる。作業の大半は Kiro CLI（Amazon Bedrock 上の Claude Opus 5.5）が行い、人は定理の記述を確認し、Lean の検査機構が証明を検査した。

  • DEV権限判断・コンテキスト管理・状態遷移のように「テストでは静かに漏れる」部分は、性質を定理として書き、実コードと差分テストで突き合わせる方法が、自作ハーネスにも応用できる。
  • PMエージェント基盤の品質保証に「境界での表現のずれ」と「稀なイベント順序」という観点を加え、権限・キャンセル周りを重点レビュー項目にできる。
  • CONSULT「エージェントの権限は親を超えない」を証明で裏付けた例は、クライアントの統制説明で使える。ただし検証対象は分析した特定コミットに限られる点も併せて伝える。
出典： AWS Japan Blog「Kiro が自身のハーネスの性質を Lean で証明する」（2026-11-03、原文は11月2日）
結果は各モデルが実コードを正しく写している前提による。修正がいつ利用者に届くかは記事に記載がない。

Thoughtworks「トークン出血」：単価は最大98%下がったのに AI 予算は増え、開発者1人あたりの消費は1年足らずで18.6倍

PMCONSULTDEV

Thoughtworks は11月3日の記事で、2024年以降にトークン単価が最大98%下がった一方、企業の AI 予算が120万ドルから700万ドル超に増え、開発者1人あたりのトークン消費が1年足らずで18.6倍になったと述べる。原因はエージェント型コーディングが同じ文脈を繰り返し送ることにある、という整理だ。事例として、ある金融機関が集中管理の制御基盤で品質を保ったままトークンの無駄を40%減らした、Uber が年間の AI 予算を4か月で使い切った、Meta が社内のトークン使用量ランキングを数日で止めた、などを挙げる。提言は、エージェントごとのトークン予算と費用の責任者を置く、月次ではなくリアルタイムで見る、実行時に自動停止する遮断器を設ける、繰り返し文脈をキャッシュする、モデルを費用と能力で使い分ける、成果に紐づけて予算を割り当てる、など。

  • PMAI 費用を「ライセンス料」ではなく「変動する計算コスト」として見積に入れ、エージェント単位の予算と上限停止を運用ルールに含められる。
  • CONSULT「単価が下がったのに請求が増える」はクライアントの CFO が必ず聞く論点で、予算・遮断器・モデル使い分けを一式の提案に組み込める。
  • DEV文脈のキャッシュと、軽い作業を小さなモデルへ回す設計は、自分のハーネスでも今日から費用を下げる手段になる。
出典： Thoughtworks「The token bleed reality」（2026-11-03）

「コーディングエージェントは自分のバグを見つけない」——テストに書かれていない欠陥を避けられた割合は、11モデルで6〜25%

DEVPM

arXiv に掲載された論文（提出は10月31日、arXiv の新着掲載は11月3日）は、タスクに明記されていない問題をエージェントが先回りして避けられるかを測るベンチマーク Foresight-SWE を提案する。4言語・35の著名 OSS リポジトリから212件を集め、各件は「最初の PR」と「その欠陥を直す後続 PR」の組になっている。元のタスクを完了し、かつ後続 PR が指摘する欠陥を作らなかった割合（FRR）は、11のモデルで6.13%〜24.53%だった。著者らは、モデルは最初の PR が持ち込む問題にほとんど対処できないと結論し、コーディング向けの学習や整合のあり方、コードレビューツールの改善に課題があるとする。

  • DEV「テストが通った」は欠陥が無い証拠にならない。エージェントの出力には、書いた本人とは別の観点のレビューを必ず通す必要がある。
  • PMAI が書いたコードのレビューと後工程の手戻りを、見積から外さずに工数として確保する根拠に使える。
出典： arXiv:2611.01181「Do Coding Agents Catch Their Own Bugs? (They Don't.)」

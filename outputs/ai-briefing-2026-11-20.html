Google、Gemini API に「Tool Retrieval」をプレビュー提供——数百のツールを登録したまま、引数の定義は必要になったときだけ読み込む

DEVPM

Google は11月19日、Gemini API の Interactions API で Tool Retrieval をプレビュー公開した。ツールに defer_loading を付けると、モデルには名前と説明だけが渡り、引数の定義（スキーマ）は検索で見つけたときに読み込まれる。検索は Gemini のサーバー側で動くため索引を自前で持つ必要はなく、1回のリクエストの中で検索、読み込み、関数呼び出しまで進む。アプリ側で検索する方式も選べるが、その場合は検索ごとに往復が1回増える。MCP サーバーのツールも遅延の対象にできる。対象は Gemini 3.6 以降と Gemini 4 の全モデル。追加料金はなく、読み込んだスキーマはその後の会話で入力トークンとして課金される。

  • DEVツールを数十個以上つなぐエージェントで、毎回すべてのスキーマを送る設計を見直せる。MCP クライアントの遅延読み込みと同じ発想が、主要な API の標準機能になった。
  • PMツールを増やすほどトークン費用が増える構造が緩む。ただし削減量は公表されていないので、自社の利用状況で測ってから見積もりに入れる。
どう試す／どう対応する：tools に {"type": "tool_search"} を加え、使う頻度の低い関数に "defer_loading": true を付ける。同じ会話ログで入力トークン数とツール選択の正しさを前後比較する（よく使うツールは遅延させないのが推奨）。
出典：Google Blog「Introducing Tool Retrieval in the Gemini API」（2026-11-19）
トークン削減や精度向上の具体的な数字はブログにない。Interactions API 限定のプレビューで、一般提供の時期は示されていない。
コメント：ツールの定義をコンテキストに入れっぱなしにしない、という設計がベンダーを問わない標準になりつつある。
重要度：高

Google、Gemini 4 の中位モデル「Neon」を公開——100万トークンあたり入力3ドル・出力15ドル、キャッシュ済み入力は95%引き、コーディングエージェントの指標で首位とする

DEVCONSULT

Google は11月18日、Gemini 4 ファミリーの新モデル Neon を公開した。最上位の Carbon と高速な Hydrogen の間に位置づけ、コンテキストは100万トークン。料金は100万トークンあたり入力3ドル、キャッシュ済み入力0.15ドル、出力15ドル。Gemini API の有料枠（AI Studio）、法人向け Gemini、Antigravity、Gemini アプリ（AI Pro／Ultra）で使える。Google は、Artificial Analysis の Coding Agent Index で1位（58.6）、Terminal-Bench 4.1 で65.2%としている。Neon が司令役となって Hydrogen のサブエージェントを並列に動かす使い方も示し、high 設定では1タスクあたりの費用が Carbon より32%低いという。

  • DEV主力モデルの比較候補が1つ増えた。SWE-sweep の成績は Antigravity 上で39.0%、簡素なハーネスでは12.8%と3倍の差があり、モデルはハーネスと組み合わせて評価する必要がある。
  • CONSULT「どのモデルを標準にするか」の相談で、Carbon と Neon の使い分けと、キャッシュ割引を前提にした費用試算を示せる。
どう試す／どう対応する：AI Studio の有料枠で、自社の代表的なタスク10件ほどを現行モデルと Neon で走らせ、成功率と1タスクあたりの請求額を比べる。
出典：Google Blog「Introducing Gemini 4 Neon」（2026-11-18）
ベンチマークはいずれも Google の発表値。日本のリージョンでの提供やデータの保存場所には触れていない。
コメント：Gemini 4 は2か月で4モデル目。モデルの入れ替わりの速さに、顧客側の評価の仕組みが追いつけるかが問われている。

CONSULTDEV

重要度：高

AWS Japan の有志が、Bedrock の API キーを参加者に自己発行させるポータルを CDK で公開——Claude Code と Codex を PoC で配るときの権限・期限・費用の統制をまとめて実装

PMDEVCONSULT

社内PoCで参加者全員に Claude Code や Codex を Amazon Bedrock 経由で使わせたいとき、キーの配布と統制が課題になる。この記事は AWS CDK（TypeScript）で、Cognito 認証、API Gateway と Lambda、DynamoDB、S3＋CloudFront からなる発行ポータルをデプロイする構成を示す。参加者ごとに IAM ユーザーを作り、許可したモデルの推論だけを許す Bedrock API キーを発行する。キーは保存せず、発行直後に一度だけ表示する。有効期限は既定7日で上限30日、管理画面から新規発行の停止、利用者ごとの一時停止・失効ができる。費用は Cost Explorer で見るが、利用者別の内訳にはコスト配分タグの有効化が必要で、反映に最大24時間かかる。Budgets は通知のみで利用は止まらない。Claude Code は環境変数4つで接続でき、モデルを必ず指定しないと403になる。AWS 公式でも長期キーは検証用途とされ、PoC 専用アカウントで動かすことが前提である。

どう試す：検証用の AWS アカウントでポータルをデプロイし、自分で1本発行して CLAUDE_CODE_USE_BEDROCK=1、AWS_REGION、AWS_BEARER_TOKEN_BEDROCK、ANTHROPIC_MODEL を設定して Claude Code を動かす。成功したら、有効期限と許可モデルを絞った状態で次のワークショップに使えるか確認する。
  • PMPoCのキー配布は「誰が・どのモデルを・いつまで・いくらまで」を最初に決める作業になる。Budgets が通知のみという点を踏まえ、利用停止は管理画面の操作で行う前提で運用を設計できる。
  • DEVBedrock 経由なら Claude Code と Codex の両方を同じキー発行の仕組みに載せられる。ただしモデル未指定の403や、IAM 反映の遅れによる発行直後の失敗など、はまりどころが具体的に書かれている。
  • CONSULTクライアントの生成AI PoC で「全員にキーを配ってよいか」と聞かれたとき、短命キー・許可モデルの限定・利用者別の失効を備えた実装例を示せる。本番は短期認証情報や SSO への移行が前提になる。

DeepSeek が V4.1 Flash を「1017」版に更新——重みを公開し、検索・取得エンドポイントは Claude Code や Codex からの利用が10月末まで無料

DEVCONSULTPM

DeepSeek は10月17日、DeepSeek-V4.1-Flash-1017 を公開し、Web サイト、アプリ、API で使えるとした。前のバージョンに比べてベンチマークの成績が上がり、タスクの完了が速く、出力が短くなったとして、性能と費用の両面で改善したと説明している。強化学習で、ゲームや3Dモデルのようなプロジェクトを最初から最後まで作る能力を高めた。重みは Hugging Face と ModelScope で公開されている。DeepSeek Harness、Tencent の CodeBuddy と WorkBuddy 向けに最適化されており、DeepSeek Harness は v0.2.1-rc.1 以降が推奨されている。あわせて、検索と取得のエンドポイントは1,000回あたり0.75ドルで、DeepSeek Harness、Claude Code、Codex のサーバー側ツールから呼ぶ分は、課金が始まる10月31日16時（UTC）まで無料とされた。ただし、モデル自体のトークン単価と API 上の正式なモデル名は公式ページに載っておらず、性能の図にも数値がない。

  • DEV重みが公開されているため、自社環境での検証や、Claude Code・Codex の検索・取得ツールの差し替えを無料期間中に試せる。性能の主張は図のみなので、手元のタスクで測ってから判断する必要がある。
  • CONSULTクライアントから低価格な中国発モデルの採用可否を聞かれる場面が増える。データの扱いと提供条件は公式ページで確認できていないため、機密データを渡す前提の提案には使えない。
  • PM10月31日で無料が終わり、検索・取得は従量課金に変わる。無料期間中に試す場合は、その後の費用を見積に入れておく。

重要度：中

QueryPie AI が機密情報の検知に特化した「判断モデル」QEV を公開——文章を型付きの区分に分類し、自社の商用 API より見逃しを減らしたと主張

CONSULTDEVPM

QueryPie AI は10月19日、Gemma 4 をベースに独自の判断AI技術で作ったモデル QEV を発表した。文章を生成せず、入力を「機密情報なし」「個人情報」「社内機密」「両方」の4区分に分類し、確率つきで返す。顧客名や連絡先、住所を個人情報、未発表の価格や割引条件を社内機密と文脈から判断し、種類や具体的な内容も特定できる。日本語・英語・韓国語の3,167文書の社内テストで、見逃しは商用の JEV API の46件に対し QEV は4件、誤検知は34件に対し50件だった。機密を含む1,281文書での検出率は99.69%としている。Hugging Face で公開され、SaaS とオンプレミスの両方で提供される。価格は個別見積である。数値はいずれも同社の社内テストの結果で、第三者による検証は確認できない。

  • CONSULT生成AIに社内文書を渡す前の情報漏えい対策として、生成モデルとは別の小さな分類モデルで入力を検査する設計を提案できる。オンプレミスで動かせる点は、データを外に出せないクライアントに合う。
  • DEVエージェントの入出力に挟む検査を、型付きの判断だけを返すモデルに任せる設計の実例である。誤検知より見逃しを減らす方向に調整されているため、止めすぎる運用になる可能性は手元のデータで測る必要がある。
  • PM検知の精度は同社のテスト条件で示された数字で、誤検知が増えるほど確認作業の工数も増える。導入前に自社データでの検証期間を見積に入れる。

Cursor のマーケットプレイスで「Claude Code」拡張の改ざん版（2.1.312／2.1.313）が約11時間配布——インストールした人は SSH 鍵の有無を今すぐ確認

DEVPMCONSULT

Cursor は10月29日（30日更新）、同社の拡張機能マーケットプレイスで Anthropic.claude-code の悪意ある改変版が配布されていたと公表した。Cursor によれば Anthropic が作ったものではない。対象は 2.1.312 と 2.1.313 の macOS・Windows 版で、配布時間は10月29日の午前2時27分頃から午後1時35分頃（太平洋時間）までの約11時間。拡張はホストとユーザーの情報を集め、攻撃者の SSH 鍵の追加、SSH サービスの有効化、リバース SSH トンネルの確立を試み、macOS では LaunchAgent、Windows ではスケジュールタスクで永続化を図った。Cursor は、鍵の追加・永続化の設置・ホスト情報の送信は行われたとしている。攻撃者のサーバーは停止中だが、拡張を消すだけでは不十分な場合があり、該当端末は隔離して再構築も検討するよう促している。他のバージョンや公式配布経路への影響の証拠は見つかっていないという。

どう対応する：この期間に Cursor で拡張を入れた・更新した端末で、authorized_keys に「svc-telemetry」の鍵がないかを Cursor の手順で確認する。あれば隔離し、その端末から触れた認証情報とセッションを別の端末から更新する。
  • DEVAI コーディング拡張は端末上でファイルとシェルに触れる高権限ソフトだ。自動更新に任せず、入手元とバージョンを固定する運用に変える理由になる。
  • PMチームの全員が Cursor・VS Code 系の拡張を入れているなら、今日中に該当有無の棚卸しが必要になる。インシデント時の窓口と連絡手順を確認しておく。
  • CONSULT「AI 開発ツールのサプライチェーンはどう守るのか」と聞かれたとき、実際に起きた配布経路の改ざん事例として示せる。クライアントの許可拡張リストの見直し提案につながる。
出典： Cursor「Security notice — malicious version of Anthropic.claude-code (2.1.313) identified in the Cursor Extension Marketplace」（2026-10-29、10-30更新）
コメント：被害の大小より、エージェントを動かす端末に「誰が作った拡張か」を確認する習慣がなかったことが露呈した点が重い。

AWS ブログが Kiro CLI で「書き込み境界」を作り1か月運用した記録を公開——変更範囲の事前宣言と差分照合、OS 層での強制

DEVPM

AWS Japan ブログ（10月30日）に、BrightFlow の池田健人氏が寄稿した。計画役の ChatGPT が MCP 経由で依頼し、Kiro CLI が実装して PR を作る仕組み「BRIDGE」を8月末から約1か月運用した記録で、主題は書き込み権限をどこに置くかである。境界は4つ。チャット側の AI に認証情報を持たせず、リポジトリと base ブランチをサーバー側で固定する。タスクごとに変更してよいファイルを宣言させ、実行後の差分と照合して宣言外ならタスクを失敗にする。Kiro は bubblewrap と seccomp のサンドボックスで動かし、AI の自己申告は判定に使わない。マージはレビューした PR の HEAD SHA と一致した場合だけ許す。運用では PR の約51%（317件）がマージされ、マージまでの中央値は32秒、GitHub 上のレビューは0件だった。19件は、レビュー後に main が進んだ状態で検証なしにマージされていた。

どう試す：エージェントへの依頼テンプレートに「変更してよいファイル一覧」を必須項目として加え、PR 作成後に差分がその一覧に収まるかを CI で照合するだけでも始められる。
  • DEV「宣言と差分の照合」と「HEAD SHA 固定のマージ」は、既存の CI とブランチ保護で再現できる。AI の自己申告ではなく環境が止める設計に寄せられる。
  • PM自動マージまで任せる場合、レビュー後に main が進む問題が実測で出た（19件）。完了条件を「PR 作成」にしない、最新 main での再検証を入れる、といった運用規程の具体例になる。
出典： AWS Japan ブログ「AI エージェントに書き込みを任せるとき、境界をどこに置くか ― Kiro CLI で仕組みを作り、1 か月運用した記録」（2026-10-30）
寄稿者自身が、この構成は AWS が推奨するものではないと明記している。数値は寄稿者の1か月分の運用による。
コメント：うまくいった数字より「未検証のままマージされた19件」を隠さず書いている点に、そのまま使える知見がある。

Mistral が約1兆パラメータの「Mistral Large 4」の重みを公開——修正 MIT ライセンス、API 提供事業者は別途契約が必要

CONSULTDEVPM

Mistral AI は、マルチモーダルで推論と指示追従を併せ持つ混合専門家（MoE）モデル Mistral Large 4 の重みを Hugging Face で公開した（リポジトリ名は 1T-A52B で、約520億の活性パラメータと推測される。ページに明記はない）。ライセンスは修正 MIT 系の「Mistral Ecosystem Open-Weight」で、利用・改変・微調整・商用化は自由だが、モデルを API として提供する事業者は商用ライセンスが別途必要になる。同社の公表ベンチマークは Terminal-Bench 4.0 が41%、BrowseComp が84.5%。vLLM や SGLang で自前環境に展開できるほか、API は入力100万トークンあたり0.70ドル、出力2.10ドルで提供される。必要な GPU 構成はページに書かれていない。

  • CONSULT「機密データを外に出さず、フロンティア級の性能を自社環境で動かせるか」という相談に、選択肢が1つ増えた。ただし1兆規模の運用コストの見積もりは別に必要になる。
  • DEV自前ホスティングを検討するときの候補になる。ハードウェア要件が未公表のため、まず API で挙動を確認してから判断する。
  • PMライセンス条項（MaaS は別契約）を調達・法務の確認項目に入れておく。ベンチマークは Mistral 自身の公表値で、第三者の再現は未確認。
出典： Mistral AI「Mistral Large 4 open weights」
ページに正確な公開日の記載はない。Hugging Face ブログの掲載（10月29日）とニュース報道から10月29日公開と判断した。

重要度：高

IBM Research が、エージェントの試行履歴から「行動ルール集」を自動で作って system prompt に足す OSS「ALTK-Evolve」を公開——τ²-bench の小売で Pass^4 が 57.5% から 67.5% に上昇

DEVPMCONSULT

IBM Research は10月20日、エージェントの「学習メモリ」を扱う OSS ライブラリ ALTK-Evolve（GitHub: AgentToolkit/altk-evolve）を紹介した。訓練タスクでのエージェントの成功・失敗をエージェントと同じモデル（GPT-4.1）に読ませ、「顧客の本人確認の手順」「取引前の確認」のような短い行動ルールに要約し、各ルールにそれを裏付けたタスク数（support count）を付けて system prompt に追記する。重みの更新も人手の注釈も要らない。τ²-bench の小売（未見のテストタスク）では、GPT-4.1 の Pass^4 が基準の 57.5% から全ルール適用で 67.5%、平均正答率は 78.1% から 82.5% に上がった。航空では Pass^4 が 35.0% から 45.0%（support 3 以上の中核ルールのみ）。リーダーボードでは小売 Pass^4 の 67.5% が首位だった。一方で費用は小売の1会話あたり $0.084 から $0.139 へ約65%増え、航空も約32%増える。ライセンスは記事に記載がない。

どう試す：リポジトリを取得し、自社で評価できるエージェントタスク（問い合わせ対応など）1種類で、ルールあり・なしの成功率と1件あたりの費用を比べる。ライセンスは導入前に GitHub 側で確認する。
  • DEVモデルを替えず、プロンプトに載るルールの形で改善できる。ルールごとに裏付けタスク数が残るため、人がレビューして不要なものを外せる点が、ブラックボックスの memory 機能と違う。
  • PM精度が約10ポイント上がる代わりに費用が3割〜6割増える。エージェント案件の見積では、精度向上策に費用の増分を併記して比較する必要がある。
  • CONSULT「エージェントは使うほど賢くなるのか」と聞かれたときに、実測値と費用増をセットで答えられる。数値は公開ベンチマーク上のもので、顧客の業務での効果は別に測る前提で伝える。

PRD 駆動のエージェント開発を成熟した企業リポジトリで測る新ベンチマーク「PACE」——最上位モデルでも要件を完全に納品できたのは 14.0%

PMDEVCONSULT

arXiv に10月19日に提出（20日に掲載）された論文は、コーディングエージェントが製品要求仕様書（PRD）を成熟したリポジトリの中でどこまで納品できるかを測るベンチマーク PACE を提案した。企業の実務に即した43タスクと、専門家が監査した750の Code Point（確認項目）からなり、要件の再構成、基準の作成、証拠に基づく評価の3段階で採点する。11のモデルとスキャフォールドの組み合わせを試した結果、多くは52.1〜78.1点に収まったが、要件を完全に納品できた割合は最上位でも14.0%にとどまった。主な障害は「実装が一部しか終わらない」ことと「部品が統合されない」ことで、個々の部品ができても全体の納品にならない。評価は専門家の合意と95.2%一致した。ハーネスを改良すると、同じモデル・同じタスクで平均が59.4から63.0に上がった。論文のタイトルが示す「レビューが追いつかない」点は、この要旨だけでは確認できない。

  • PMエージェントが「動くコード片」を出しても、要件の充足や統合は別に検収が要る。見積やスケジュールで、統合と受入の工程を AI 作業の後ろに明示的に置く根拠になる。
  • DEVPRD を渡して任せる運用では、要件ごとにチェックリスト化して差分を確認する仕組みが必要になる。ハーネスの改良だけでも点数が動く点は、モデル選びより先に手を入れる余地を示す。
  • CONSULT「AI に仕様書を渡せば作ってくれるのか」と聞かれたとき、完全納品が14%という数値で、過度な期待を抑える材料になる。
出典： arXiv:2610.26394「When Coding Agents Outpace Review: Evaluating PRD-Driven Development in Mature Enterprise Repositories」（2026-10-19）

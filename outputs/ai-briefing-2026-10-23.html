Claude Code のフックで止めたはずの ~/.claude への書き込みが、Bash の ln・touch では通っていた——利用者が実測して公開

DEVPMCONSULT

個人開発者が10月22日（23日更新）に公開した記事は、Claude Code のフックで Edit|Write にゲートを掛けても、Bash の ln・touch・rsync・mv で ~/.claude 配下のファイルを書き換えられたと報告している。観測は9月8日〜28日、Claude Code 2.1.270・macOS 13.7.8。原因は、フックの matcher がツール名で起動するため Bash の呼び出しではゲートが動かず、Bash 向けの文字列検査も ln・rsync・touch を書き込みの語として数えていなかったことだと筆者は述べる。逆に、2>/dev/null や引用符内の > で読み取りだけのコマンドが誤って止まる誤検知もあった。リダイレクトの除去（9/19）と、ゲートが開いている間の Bash 書き込みを判定役サブエージェントとバックアップ経由にする対策（9/12）は入れたが、ゲートが閉じている間の ln・rsync・touch の検出漏れは未解決という。

どう試す：自社で使っているフックの matcher が Bash を含むか確認し、保護対象のテスト用ファイルに ln -sf や touch をかけて、書き換えが止まるかを試す。止まらなければ、文字列照合に頼らない制限（権限の deny 規則やサンドボックス）の併用を検討する。
  • DEVツール名単位のフックは、別のツール経由の同じ操作を止めない。「書き込みを禁止した」設定は、書き込める経路ごとに実際に破れるか試して初めて言える。
  • PMエージェントの権限統制をフックで説明している案件では、検証した経路の範囲を確認してから「統制済み」と報告する。未検証の経路は残余リスクとして計上する。
  • CONSULTクライアントから「エージェントの書き込みは制限済み」と聞いたとき、Bash などの別経路での再現テストを実施したかを確認する観点になる。
出典： Zenn「Claude Codeのフックで止めたはずの書き込みが、Bashのlnやtouchで通っていた」（2026-10-22 公開）
個人の環境での観測で、確認したのは筆者自作のフック4本のみ。Edit|Write だけにゲートを掛けた他の環境で同じ穴が開くという点は筆者の推測で、Claude Code 本体の仕様は確認していない。観測日は9月で、現行バージョンでの再現は未確認。

Anthropic が Agent Skills の標準を Agentic AI Foundation（Linux Foundation 傘下）に寄贈——70 超のプラットフォームが対応、公開スキルは約100万

DEVCONSULTPM

Anthropic は10月22日、エージェントに専門知識や手順を渡す Agent Skills のオープン標準を、Agentic AI Foundation（AAIF）に寄贈すると発表した。AAIF は Anthropic、Block、OpenAI が共同設立した Linux Foundation 傘下の団体で、MCP もすでに寄贈されている。寄贈の対象は標準そのもののほか、名称とロゴ、GitHub の組織、agentskills.io のドメイン。Anthropic、Google、OpenAI などのエンジニアが個人の立場でメンテナを務め、リード・メンテナは David Soria Parra 氏と Mahesh Murag 氏。提案中のロードマップには、バージョン付きのリリース、正式な提案手続き、スキルの作者と導入者向けのセキュリティ指針が入っている。Anthropic によると、2025年12月の公開以降、ChatGPT、Cursor、GitHub Copilot、VS Code を含む70超のプラットフォームが対応し、公開されたスキルは約100万、インストールは約2億8000万回に達した。利用者に必要な手続きはない。

  • DEVスキルを特定ベンダー専用でなく、複数のエージェントで使い回せる資産として作る前提が固まる。外部のスキルを入れる際は、セキュリティ指針が出るまで提供元を自分で確認する。
  • CONSULT「エージェント基盤のロックインは大丈夫か」への答えとして、MCP に続き Skills も中立の財団に置かれたことを示せる。ロードマップは「提案中」の段階である点は添える。
  • PM社内の手順をスキルとして整備する投資が、特定製品の寿命に左右されにくくなる。スキルの棚卸しと審査の担当を決める時期の目安になる。

AWS が AI コーディングエージェント Kiro の自己修正の仕組みを公開——自分の実行軌跡を読んで61,742回届いた誤った一文などを見つけ、最初の1週間で8件の PR を作り7件をマージ

DEVPMCONSULT

AWS Japan のブログ（10月21日公開）は、Kiro のツール説明に、ハーネスの動作について事実と異なる一文があり、数百のセッションで61,742回モデルに届いていたのに誰も問題にしていなかったと述べる。Amazon は Kiro 自身の実行軌跡を読んで失敗や無駄を探す社内システム「kiro-trace」を作った。モデルが変更を提案し、受け入れるかどうかは決定的なコードが判定する。最初の1週間で8件の PR を作り7件がマージされ、冗長なファイル再読み込みの約83%削減、読み取りツールの拒否205件とサブエージェントの拒否167件の解消、約8回に1回失敗していた検索の修正などが入った。検証は、対象の失敗の再現確認、過去の修正をすべて含む退行テスト（100%維持が必須）、リリース前のベンチマーク（89タスク×各5回）の3段階で、最終的なマージは人が行う。削減したツール構成では Terminal-Bench 2.1 の pass@1 が77.5%から82.4%に上がりトークン費用は約3分の1とされるが、既定への反映は製品判断が必要で未リリース。

  • DEVCLAUDE.md やツール説明に書いた一文が実際に効いているか、実行ログで確かめる発想を取り入れられる。まず自分のエージェントの拒否ログと再読み込みの回数を数えるだけでも手がかりになる。
  • PM修正を受け入れる判定を決定的なコードに置き、最終マージを人に残す構成は、エージェントによる自己改善を統制する実例として使える。

Anthropic が常時稼働型の個人エージェント「Claude Duet」をリサーチプレビューで公開——米国の Pro / Max 向けウェイトリスト、Team / Enterprise は対象外

CONSULTPM

Claude Duet は、メッセージ（テキストまたは音声）で頼むと Anthropic のクラウド上の専用環境で作業し、終わったときや判断が要るときに連絡してくる個人向けエージェント。Claude Opus 5.5 をベースにし、Claude の記憶、スキル、アプリのほか、Gmail・Slack・Stripe・QuickBooks など6,000超のコネクタとプラグインを使う。受信箱とカレンダーの確認、返信の下書き、未払い請求書への催促の下書き、資料や表の作成を例に挙げる。メッセージの送信や支払いなど重要な操作は承認を求め、承認・ログイン・安全確認は利用者専用のクラウド環境内で行われる。提供は米国の Pro・Max 契約者向けのウェイトリスト制で、iOS・Android アプリと claude.ai で使える。別料金はなく、定期的な背景確認も含めて契約プランの利用上限を消費する。ページ自身が、スレッドの読み違いや緊急度の誤判断、確認と確認の間に届いたものの見落としがありうると明記している。

  • CONSULTクライアントの従業員が個人契約の Pro / Max で業務メールや社内 Slack をつなぐ「個人利用のエージェント」が現実になる。利用規程で、会社のデータを接続してよい範囲を先に決めておく話につながる。
  • PM利用上限を背景処理と共有するため、大きな作業は想定より早く上限に達しうる。業務利用の費用見積の対象は Team / Enterprise が対象外の間は立てにくい。

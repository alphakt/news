コーディングエージェントのコンテキストを削ると、キャッシュ割引がある料金では費用が最大116%増える——2万回超の実行で測った研究

DEVPM

11月17日に arXiv に投稿された研究は、コーディングエージェントに関連コードを先に渡す方法と、古いツール出力を削る方法が費用をどう変えるかを測った。オープンモデルで SWE-bench Verified、SWE-bench、Loc-Bench を2万回以上実行し、キャッシュなしの入力、キャッシュ済み入力、出力を分けて数えた。関連コードを先に渡すと検索・読み込みのコマンドは18〜34%減ったが、キャッシュ済み入力が通常の10分の1の料金では費用が33〜42%増え、解決率に有意な改善はなかった。古い出力を削る方法は、キャッシュ割引がなければ19〜36%安くなる一方、割引があると38〜116%高くなった。短いプロンプトでも手順が増えれば安くならない、としている。

  • DEV履歴を途中で書き換えるとキャッシュが効かなくなる。コンテキストの圧縮や削除を入れる前に、実際の料金体系で費用を測る。
  • PM「トークンを減らせば安くなる」は前提にできない。費用の見積もりは、キャッシュの効き具合と手順の数を含めて立てる。
出典：arXiv 2611.22238「Context Has a Price: Adding and Removing Context for LLM Coding Agents under Prefix Caching」（2026-11-17）
対象はオープンモデルで、商用のエージェント製品では測っていない。著者の所属はページに記載がない。同時に走らせた実験どうしがキャッシュを共有し、費用の比較がゆがむ点にも注意を促している。
コメント：コンテキスト管理の良し悪しは、トークン数ではなく請求額で比べるべきだという、当たり前だが見落としやすい指摘。

JA共済連、基金の支出判断を支える AI エージェントで人の判断との一致率7〜8割に——過去の照会約600件を1件ずつのファイルに分け、先に「争点」を出させる

  • CONSULT「社内データを入れたのに精度が出ない」という相談への具体的な処方として使える。データを事例単位に分けることと、判断の前に論点を出させることの2点。
  • PM一致率7〜8割の段階で、AI を最終回答ではなく担当者の下調べに位置づけている。検証計画で「何割なら何に使うか」を先に決める参考になる。

エージェントの操作を「元に戻せるか」で5段階に分類する提案——MCP サーバー20個・536ツールに付与し、攻撃とみなせる29件すべてで実行前に止めた

DEVPM

11月17日に arXiv に投稿された論文は、ツールを使う権限があることと、その結果を元に戻せることは別だと指摘し、5段階の「Reversibility Classes」を提案した。引数によって段階が変わる規則、迷ったら厳しい側に倒す既定、実行前の状態を保存する約束をあわせて定める。MCP サーバー20個の536ツールに段階を付けた登録簿を作り、ファイル、Git、SQLite、3種のブラウザで実験した。記録済みの2,158回の実行では、攻撃とみなせる29件すべてで該当操作の前に止め（読み書きだけで区別する方式は18件）、通常の1,209回で増えた承認は9回だった。ただし登録簿全体の正確さや実運用での被害減少は示せていない、と著者は書いている。

  • DEV承認を求める条件を「書き込みかどうか」ではなく「元に戻せるかどうか」で決めると、承認の回数を増やさずに危ない操作を止めやすい。自前のフックやゲートの設計に取り入れられる。
  • PMエージェントに任せる範囲を決める際、操作ごとに戻し方があるかを一覧にしておくと、権限の議論が具体的になる。
出典：arXiv 2611.22075「Can You Undo It? Reversibility Classes for AI Agent Actions」（2026-11-17）
5段階の具体的な定義は要旨ページになく、確認していない。MCP の既存の注釈と登録簿の段階は、比較できる481ツールのうち118で食い違った。段階付けの確認は AI 支援のレビュアー1名によるもので、独立した評価ではないと著者が断っている。
コメント：「承認が多すぎて誰も読まない」問題への一つの答え。分類そのものより、戻せない操作だけに人を置くという考え方が使える。

curl 作者、エージェントによる Rust 書き直しを数字で評価——C 18.5万行が Rust 34万行になる間に、本家は300超のコミットと200余りのバグ修正を重ねた

PMDEV

curl の作者 Daniel Stenberg 氏は11月17日、AI エージェントで作られた curl の Rust 版（urlx と kov/curl）について書いた。氏の数えでは、約18.5万行の C が約34万行の Rust に書き換えられた。kov/curl の作者は8,600ドルかけたと主張しているが、コメント欄では API 換算の推計だと指摘されている。同じ期間に本家の curl は300を超えるコミットを取り込み、200余りのバグ修正といくつかの脆弱性修正を行ったが、Rust 版にはどれも入っていない。2026年に確認された curl の脆弱性81件のうち、メモリ安全な言語で防げたとみられるのは14件（17.3%）だという。氏は、価値はコードではなく、長年の改良、利用者と貢献者の共同体、保守者、ABI と API の安定性にあると述べた。

  • PMAI による移植は作るまでが速くても、元のコードの修正に追従し続ける費用が残る。移行計画では書き換え後の追従の体制まで見積もる。
  • DEVメモリ安全な言語への書き換えで防げる欠陥は全体の一部に限られる、という具体的な数字として使える。
出典：daniel.haxx.se「Actual curl rewrites in Rust」（2026-11-17）Simon Willison による引用（2026-11-18）
氏は2つの Rust 版の作者とは連絡を取っておらず、他人から送られたリンクで知ったという。Rust 版を本家に取り込むかどうかには触れていない。

Claude の個人向け有料プランが「Max」「Ultra」に改称——Ultra（月200ドル）は検証済みアカウントで5時間ごとの利用制限が撤廃

CONSULTPMDEV

Anthropic は10月30日（米国時間）、月100ドルの「Max 5x」を「Max」に、月200ドルの「Max 20x」を「Ultra」に改称した。価格は据え置きで、既存の契約者は自動で移行する。ヘルプページによれば、Ultra は Pro の10倍の利用量を週単位で提供し、全モデル共通の週間上限と Fable 用の別の週間上限がある。検証済みのアカウントでは5時間ごとの上限（Current session）がなくなる。検証は口座と決済の履歴で自動的に行われ、未検証のアカウントには一時的な5時間上限が残るが、自動で外れる。確認方法は Settings > Usage を開き、「Current session」のバーが出なければ検証済みである。旧「20x」は5時間枠の倍率だったため、新しい「10x（週単位）」と単純には比べられない。

どう試す：Claude を個人契約で使っているメンバーは Settings > Usage を開き、Current session バーの有無で5時間上限が外れたか確認する。チームの利用計画書にある「Max 20x」の表記は「Ultra」に置き換える。
  • CONSULTクライアントから「Claude の上位プランは何が変わったか」と聞かれたとき、価格は同じで、5時間制限の撤廃と週単位の倍率表記に変わった点を正確に説明できる。
  • PM長時間のエージェント作業が5時間枠で止まる前提で組んだ工数・運用ルールを見直せる。週間上限は残るため、上限到達の管理は引き続き必要である。
  • DEVClaude Code を長時間回す人にとって、セッション途中の制限待ちが減る可能性がある。実際の効き方は検証状況に依存する。

GitHub Copilot Fusion が一般提供——タスクごとにモデルと実行パターン（Single／Cascade／Critique）を自動選択、有料プランは11月30日までモデル費用30%割引

DEVPMCONSULT

GitHub のドキュメントによると、Copilot Fusion はタスクごとにモデルと実行パターンを選ぶ実行時ルーターである。Single は1モデル、Cascade は効率型モデルの草案を判定役が受理するかより高性能なモデルへ回し、Critique は草案を複数モデルが並列でレビューして元のモデルが直す。作業レベルは Standard（全プラン）、High（Pro+ 以上）、Max（Max／Business／Enterprise）。Fusion 自体に追加料金はなく、使ったモデルごとの標準料金がかかる。High と Max は複数モデルを使うため消費が増えうる。有料プランでは2026年11月30日までモデル費用が30%割引になる。VS Code、Copilot CLI、GitHub Copilot app、JetBrains で使え、管理者ポリシーやデータ常駐の制限でモデルが使えない場合はモデルピッカーに出ない。ローカルモデルの自動ルーティングは公開プレビューである。

どう試す：VS Code のモデルピッカーで特定のモデルではなく「Copilot Fusion」を選び、日常のタスクを Standard で数日流す。応答下の作業レベル名にカーソルを合わせると使われたモデルを確認できる。
  • DEVモデル選びの手間を減らせる。Critique は別系統のモデルが自分の草案を見直すため、AI 生成コードのレビュー前段として試す価値がある。
  • PM料金は使用モデル単位の従量で、High と Max は消費が増えうる。30%割引の期間（11月30日まで）に自チームの消費量を測り、割引終了後の費用を見積もっておく。
  • CONSULT「どのモデルを使うべきか」という相談に、単一モデルの選定ではなくルーティングで運用するという選択肢を提示できる。管理者ポリシーによる制限も説明材料になる。

Hono が10月5日から外部 PR の受付を停止——AI で PR 数が82件から345件に増え、「コードの希少性が消えた」と説明

PMDEVCONSULT

Hono の作者 Yusuke Wada 氏が11月1日の FOSS4G 分科会シンポジウムで、Hono が10月5日から外部コントリビューターの PR を受け付けず、PR を出せるのは collaborator のみにした理由を説明した。7〜9月の PR 数は2025年の82件から2026年は345件に増え、朝に十数件が届く日や、issue を立てた直後に修正 PR が付く例があった。氏は「AI スロップ」が問題なのではなく、モデルの改善でコード品質は上がったと述べる。問題は、直す必要のない箇所を探して履歴書や景品のために出す PR が増えたことと、コードを誰でも書けるため、メンテナ自身が書けば足りることだという。代替として、issue での実需の報告、変更のレビュー依頼、issue に fork ブランチを貼る方法（メンテナが PR 化し、貢献者は共同作者として残す）を挙げている。

  • PMAI でコードの供給が増えた結果、レビューする側の時間が最大のボトルネックになる。OSS を依存先にする計画では、メンテナの受付方針の変更を依存リスクとして管理できる。
  • DEVOSS に貢献する際、PR を出す前に issue で実需を書く手順が必要になる場合がある。社内の自社 OSS・共通ライブラリでも、同じ受付ルールを検討できる。
  • CONSULTAI 導入後に「コードは増えたがレビューが追いつかない」と訴えるクライアントに、受付を絞る選択肢を実例として示せる。
出典： Yusuke Wada「HonoがPRを閉じた理由」（FOSS4G 2026、2026-11-01）

OpenAI・Google・Microsoft が robots.txt の共通トークンで AI 学習の可否を示す仕組みに対応表明——Microsoft は2027年2月1日から参照、Anthropic も実装中

CONSULTPM

ITmedia の報道によると、OpenAI、Google、Microsoft は10月30日（米国時間）、Web サイト運営者が AI 学習への利用可否を一括で示せる共通の仕組みに対応すると発表した。提案は Anthropic の担当者による IETF の個人 Internet-Draft で、まだ標準ではない。User-Agent の下に共通トークン「__usage_ai-training」を置き、Disallow で拒否、Allow で許可を示す。クロール自体の制御は従来のクローラー別ルールのままである。Google は、共通シグナルで拒否し Google-Extended を明示していない場合は、Google-Extended も拒否とみなす。Microsoft は2027年2月1日から読み取りを開始し、従来の NoArchive／NoCache は3月1日までの移行を求める。OpenAI は数か月以内、Google は2027年を目標とし、Anthropic は時期を示していない。

  • CONSULT自社サイトやクライアントの公開コンテンツの AI 学習利用に関する方針を、robots.txt で一括して示せるようになる。2027年の対応開始前に、方針を決める作業を提案できる。
  • PMWeb サイトを運用する案件では、robots.txt の設定変更と、Microsoft の移行期限（2027年3月1日）をスケジュールに入れる必要がある。

Zenn「AI に作らせた PR のうち、人のレビューを省けたかもしれないものを、過去の PR のファイル名で数える」——自動マージ可否をパスの規則で仕分ける

PMDEV

Zenn の記事（11月2日）が、Claude Code に PR を作らせている会社で、人のレビューを省けた可能性のある PR をどう数えるかを示す。`gh pr list --json files` で変更ファイル名を集め、2つの正規表現リストで仕分ける。一つはレビューを省きうるファイル（予測コード、そのテスト、バージョンファイル）、もう一つは触れさせないファイル（CI、デプロイ設定、課金、Dockerfile、マイグレーション）である。各 PR は「never（1つでも該当）」「auto（全ファイルが auto）」「review（それ以外）」に分かれる。10月15〜18日は4件中1件（約25%）が auto だった。あくまで「省けたかもしれない」件数で、安全の検証ではなく、CI 状態やブランチは見ていないと著者自身が断っている。

  • PMAI の PR のレビュー工数を、過去の変更ファイルから見積もる最小手順になる。レビュー必須の領域を先に決める議論の材料にできる。
  • DEV「never」リストに CI やマイグレーションを置く発想は、リポジトリごとの自動マージ範囲の設計にそのまま使える。

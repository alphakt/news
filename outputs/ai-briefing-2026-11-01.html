Claude Code 2.1.314／2.1.316 が作業ディレクトリ外への書き込みを設定で禁止できるように——Opus 4.8 の fast mode は11月30日に削除

DEVPMCONSULT

Claude Code の変更履歴によると、10月30日公開の 2.1.314 で permissions.blockWritesOutsideWorkingDirectories が加わった。true にすると Write・Edit・NotebookEdit が作業ディレクトリ外のパスをどの権限モードでも拒否する。同版では、claude -p --resume で入った worktree にサンドボックスが効いていなかった問題も直った。31日公開の 2.1.316 では、Opus 4.8 の fast mode が10月30日付で非推奨となり、11月30日に削除される。削除後の fast mode 要求はエラーになり、通常の Opus 4.8 へは切り替わらない。速度を保つには Opus 5.5 へ移る必要がある。管理者設定の autoMode.allow や --restricted セッションのファイル送信に関する修正も入った。

どう対応する：チームの settings.json に blockWritesOutsideWorkingDirectories: true を入れて、普段の作業が止まらないか試す。あわせて fast mode を指定している設定とスクリプトを検索し、11月30日までに Opus 5.5 へ置き換える。
  • DEV書き込み範囲の制限をプロンプトの約束ではなく設定で強制できる。AI に任せる作業の「やってはいけない範囲」を、リポジトリ共通の設定として配布できる。
  • PMfast mode を指定した定時タスクや CI は、11月30日以降エラーで止まる。期限付きの変更として、使用箇所の棚卸しを今月中の作業に入れたい。
  • CONSULTクライアントのエージェント導入では「どこまで書き換えられるか」が必ず聞かれる。管理者設定で書き込み範囲を強制できる具体例として、そのまま提示できる。
出典： Claude Code 変更履歴（2.1.314：2026-10-30／2.1.316：2026-10-31）

Kiro のブログが「仕様のハードニング」を公開——コードを生成する前に、要件へ CWE 由来のセキュリティ制約を EARS 形式で追記する

DEVPMCONSULT

Kiro ブログの記事（10月30日）の日本語版が、31日付で AWS Japan ブログに載った。仕様の多くは機能だけを書き、誤用されたときの振る舞いを書かないため、機能テストは通っても脆弱性が残る。記事は、60の CWE を8領域に分けたライブラリで要件中のキーワードや正規表現から該当を検出し、足りない制約を [SECURITY: …] タグ付きで requirements.md に追記する方法を示す。認可の不備のような字句で拾えない問題は、エージェントの意味的レビューで補う。追記は差分で採否を決められる。SAST・DAST・人のレビューの代わりではなく、実験的な取り組みと明記されている。

どう試す：既存の requirements.md に上記4項目を書き足し、AI が出した差分をレビューするとき、仕様のどの行に対応するかを確認する。Kiro なら「harden my specs」と依頼すれば試せる。
  • DEV「認証失敗時は拒否」「入力検証」「パラメータ化クエリ」「返却項目の最小化」を仕様に書いておけば、エージェントが従う具体的な目標になる。Kiro 以外の仕様駆動でも真似できる。
  • PMセキュリティの確認をコード完成後の検査から、仕様レビューの段階へ前倒しする工程設計の例になる。仕様の追記を誰が承認するかを、役割として決めておく必要がある。
  • CONSULTAI 開発の品質統制を相談されたとき、「実行時の防御」とは別の「上流の統制点」として提案できる。

Cisco Talos が、盗んだデータを LLM に渡して被害者の「価値」を順位づけするインフォスティーラー VOLTA を報告

DEVPMCONSULT

Cisco Talos のブログ（10月31日）によると、VOLTA は認証情報、セッション、暗号資産ウォレット、SSH やクラウドの鍵などを盗んだあと、集めたデータを JSON にして OpenRouter 経由で LLM に送る。LLM は「フォレンジック分析官」として、資産を収益化しやすい順に並べた評価と、被害者のパスワード管理の癖を返す。既定のモデルは anthropic/claude-opus-4.6 で、拒否応答を検知すると別のモデルに切り替わる。攻撃者はモデルの拒否を想定していたと考えられる。Talos は、非開発者のプロセスによる Chrome の --headless 起動を制限すること、認証情報をハードウェアで保護された保管庫に置くことなどを勧めている。

  • DEV開発端末は SSH 鍵やクラウドの鍵を持つため、評価で上位に置かれやすい。鍵を端末内のファイルではなくハードウェア保護の保管庫に移す理由が具体的になる。
  • PM端末侵害時の初動に、トークンの失効とパスワード変更の担当・手順を入れておく。復旧の対象に「開発者の端末にある各種鍵」を含めること。
  • CONSULT「攻撃側も AI を使う」という相談に、被害者の選別という実例で答えられる。防御の提案では、端末のアプリケーション制御を入口にできる。
出典： Cisco Talos「Appraisal by AI: Model-driven victim prioritization in the VOLTA infostealer」（2026-10-31）
コメント：AI が攻撃を自動化するというより、攻撃者の「次に何を狙うか」の判断を肩代わりしている点が実務上の新しさである。

デジタル庁が「源内」に国会答弁の作成支援アプリ（プロトタイプ）を追加——約18万人の職員が試験利用、責任は答弁者に残す設計

CONSULTPM

デジタル庁は、ガバメントAI「源内」に、国会答弁案の作成を支援するアプリのプロトタイプを加えた。政府職員の約18万人が使える。情報の検索と整理、答弁案の生成、内容の検証支援を行う。開発では16省庁が公募した実務経験のある職員102名が評価者として画面や機能に意見を出し、一部は改修に反映された。第222回臨時国会で試験的に提供し、有効性・操作性・出力品質を実業務で検証して、来年1月の通常国会で本格提供する計画である。AI の出力はそのまま使わず、根拠資料との照合を職員が行い、答弁の責任は答弁者が負うと明記されている。

  • CONSULT「AI の出力に誰が責任を持つか」という問いに、官公庁が公式に書いた運用原則を示せる。社内文書の起案支援を提案する際の根拠になる。
  • PM現場の職員を評価者に入れて試験運用し、結果を見て本格提供する進め方は、そのまま導入計画の型として使える。

InfoQ 公開の講演「はしごの段が抜けている」——AI が若手の下積みを代替すると、レビューと育成が先に詰まる

PMDEVCONSULT
